Feature

Start-up

What the person sees while their data opens, and the way out when it cannot be opened: try again, restore a backup, or start from zero.

Purpose

Covers the moment before the app exists: a bare loading desk while the data opens, and, if the data will not open, a screen that holds no figure from that data and offers three ways forward. Nothing is deleted from here without a typed confirmation or a checked backup.

Entry points

  • App start, while the data is opening (StartupState.Opening): app/src/main/java/com/software/sello/MainActivity.kt:57. Drawn in the default theme, since the stored appearance is not readable yet.
  • App start, when the data could not be opened (StartupState.Failed): app/src/main/java/com/software/sello/MainActivity.kt:76. Also drawn in the default theme. When the data opens (after Intentar de nuevo), StartupState.Ready replaces this screen with the app; there is no navigation call.
  • Leaves through onStartedOver once the data was set aside (app/src/main/java/com/software/sello/feature/startup/StartupFailureScreen.kt:68), and through an app restart after a restore (StartupFailureAction.Leave).

Screen: Loading at start

Layout

  1. A full-screen box filled with SelloTheme.colors.desk. No slip, skeleton, spinner or text on screen.
  2. For accessibility services it is one indeterminate progress node described as "Cargando" (sello_loading, :design-system). Source: app/src/main/java/com/software/sello/feature/startup/StartupLoading.kt:22.

Screen: Data could not be opened

Layout

  1. SelloScaffold titled with the app name (app_name; the debug build shows "Sello Debug"). No tabs, dock or back arrow. The content column scrolls, with the scaffold padding outside the scroll so the keyboard shrinks the visible area (StartupFailureScreen.kt:107).
  2. Explanation slip (Slip, pinked edge): heading "No pudimos abrir tus datos" in headlineSmall, body in bodyLarge inkSoft, an optional FieldMessageText after a retry that still failed, then three full-width SelloButtons: "Intentar de nuevo" (filled), "Restaurar un respaldo" (outlined), "Empezar de cero" (outlined). StartupFailureScreen.kt:132.
  3. Restore step, below the choices, scrolled into view when it appears (StartupFailureScreen.kt:185): an ErrorSlip for a rejected file or an interrupted restore, a plain preview slip, or the shared RestoredSlip (app/src/main/java/com/software/sello/presentation/restore/RestoreSlips.kt:58, also used by Respaldo).
  4. An optional FieldMessageText when the data could not be set aside (StartupFailureScreen.kt:120).
  5. Start-over warning slip (plain Slip), below everything and scrolled into view: heading, two paragraphs, a FormField for the word, and a row of two buttons side by side (StartupFailureScreen.kt:285).

Controls

  • "Intentar de nuevo": StartupFailureAction.Retry; opens the data again. If it opens, the app replaces this screen; if not, the still-failing line shows. Disabled once a restore began.
  • "Restaurar un respaldo": RestoreBackup; asks the root to open the system's document picker (OpenDocument, any type). The answer is Chosen(uri); a dismissed picker or no picker app is Chosen(null) (StartupFailureScreen.kt:72).
  • "Empezar de cero": StartOver; opens the warning slip.
  • Word field: Typed(text), kept exactly; characters keyboard, no autocorrect.
  • Warning "Cancelar": Cancel; closes the warning and clears the word. Warning "Empezar de cero": Confirm; sets the data aside, then the activity starts over.
  • Preview "Restaurar el respaldo": ConfirmRestore. Preview "Cancelar": CancelRestore.
  • "Continuar" after an interrupted restore and the RestoredSlip's leave button: Leave, which restarts the app. The RestoredSlip can also send ApplyPreferences.
  • System Back: closes the warning or a preview or rejection first; after a restore began it is Leave; otherwise it leaves the app (StartupFailureScreen.kt:89).

Feature-local parts that look like shared ones

  • Start-over warning slip (app/src/main/java/com/software/sello/feature/startup/StartupFailureScreen.kt:285) is a typed-word confirmation like Reset's word slip (app/src/main/java/com/software/sello/feature/reset/ResetScreen.kt:191) and Category removal's (app/src/main/java/com/software/sello/feature/category/CategoryRemovalSlips.kt:433). It differs: a headlineSmall heading instead of RestoreHeading, the two buttons side by side in a Row (Cancelar first) instead of stacked full width, no busy state, and the field never disabled. The same screen's backup preview stacks its buttons like Reset. No screenshot of either slip. Finding: M08.
  • Explanation slip resembles ErrorSlip (a failure with a retry) but is left-aligned with three stacked choices; that difference has a reason (three ways out, not one retry).

Findings here

Places in this feature on the findings page; shared parts it uses are listed there under their own files.

Gaps

  • Loading at start: drawn before Sello's theme and screens exist, so a JVM screen test has nothing to show.
  • Preview and restoring on this screen: no screenshot (they need a checked backup file).
  • Busy (retry or set-aside running): not drawn at all, so there is nothing to capture; see the findings.
  • startup-failure is captured in Cobalto and Violeta, light and dark, but the real screen always uses the default theme (app/src/main/java/com/software/sello/MainActivity.kt:74); only the default light/dark captures match what a person can see.
