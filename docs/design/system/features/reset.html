Feature

Reset

Borrar datos: erase the whole history and return Sello to first run, after two confirmations.

Purpose

Lets a person erase every category, expense, income, goal, schedule and investment and put the preferences back to their first-run values. It asks twice: first with the counts of what goes, then with the word BORRAR. Backup files saved outside Sello are never touched. After an erase, every way out restarts the app.

Entry points

  • "Borrar todos los datos" in Configuración's Tus datos slip: app/src/main/java/com/software/sello/feature/backup/TusDatos.kt:137, navigating with app/src/main/java/com/software/sello/navigation/SettingsDestinations.kt:49.
  • The destination: ShellScreen titled "Borrar datos" (reset_title), no entry dock, no past-month ribbon; the back arrow runs ResetViewModel.back(): app/src/main/java/com/software/sello/navigation/ResetDestinations.kt:25, ResetDestinations.kt:33.
  • An erase an earlier process committed but did not finish is finished when the session is created, and shown only if its preferences still fail: app/src/main/java/com/software/sello/feature/reset/ResetSession.kt:53.

Screen: Borrar datos

Layout

One scrolling Column with spacing.md gaps holding exactly one slip for the current step (app/src/main/java/com/software/sello/feature/reset/ResetScreen.kt:90).

  1. First confirmation (Counts, ResetScreen.kt:144): an unpinned Slip; an optional warn-coloured "data changed" note; RestoreHeading "¿Borrar todos tus datos?"; two RestoreBody paragraphs (what goes, as one sentence, and that backups stay); an outlined "Cancelar" and a Loss SelloButton "Continuar" in a ButtonPair (1:2), stacked when a label does not fit: Continuar on top, Cancelar under it.
  2. Second confirmation (Word, ResetScreen.kt:192): an unpinned Slip; "Escribe BORRAR"; "Esto no se puede deshacer. Sello quedará como recién instalado."; a FormField "Escribe BORRAR para confirmar" (capitals, no autocorrect, Done); an outlined "Cancelar" and a Loss "Borrar todo", enabled only when the trimmed text is exactly BORRAR, in a ButtonPair like the first step's.
  3. Done (Erased, ResetScreen.kt:229): "Tus datos" with a landing Stamp "Borrado" (StampInk.Good), "Sello quedó como recién instalado. Tus respaldos fuera de Sello no se tocaron." and a filled "Empezar de nuevo".

Controls

  • Continuar: ResetAction.Continue, opens the word step (ResetViewModel.kt:46).
  • Cancelar on the counts: closes the screen (onClose, ResetScreen.kt:182).
  • Word field: ResetAction.Typed, kept exactly as typed (ResetViewModel.kt:48).
  • Borrar todo: ResetAction.Confirm; checked again in the ViewModel, which closes the word step and starts the erase with a new operation ID (ResetViewModel.kt:53, ResetSession.kt:80).
  • Cancelar on the word: ResetAction.Cancel, back to the counts with the field cleared.
  • Intentar de nuevo (unreadable counts or a failed erase): ResetAction.Retry, counts again; Comprobar: ResetAction.Check; Restablecer preferencias: ResetAction.ApplyPreferences; Empezar de nuevo: ResetAction.Leave, restarts the app.
  • Back (arrow and system, both through ResetViewModel.back(), ResetScreen.kt:72): restarts once erased or unknown, does nothing while erasing, closes the word step, else closes the screen.

Feature-local parts that look like shared ones

  • The word step (app/src/main/java/com/software/sello/feature/reset/ResetScreen.kt:192) is the same idea as category "Borrar todo", which puts the field in a ConfirmSlip with confirmEnabled (app/src/main/java/com/software/sello/feature/category/CategoryRemovalSlips.kt:136), and start-up's "Empezar de cero" (app/src/main/java/com/software/sello/feature/startup/StartupFailureScreen.kt:285). All three keep their own CONFIRM_WORD = "BORRAR" and their own copy of "Escribe BORRAR para confirmar". Compare reset-cobalto-light-font1.0.png with category-removal-all-typed-cobalto-light-font1.0.png.
  • What goes is one sentence here; category delete-all lists the same kind of facts as ChangeRows (category-removal-all-cobalto-light-font1.0.png).
  • "Borrado" heading row (ResetScreen.kt:231) is the same FlowRow + landing stamp as RestoredSlip's "Restaurado" (design-system/src/main/java/com/software/sello/designsystem/component/Restore.kt:79).
  • Refreshed note (ResetScreen.kt:152) is written again in Restaurar (app/src/main/java/com/software/sello/feature/backup/RestoreSection.kt:171), in the same warn ink.
  • Counting shows a SlipSkeleton here; category removal counts in a dialog with a spinner and words (CategoryRemovalSlips.kt:93), and shows "Aún no se puede borrar" with an ActionFailed StatusSlip inside that dialog when counting fails (category-removal-count-cobalto-light-font1.0.png), where this screen uses a LoadFailed StatusSlip.
